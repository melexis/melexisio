Connect to a board.
Every network the board has joined, most recent first, up to ten — in range or not. Whether one is in range comes from the last scan. A known network joins with no password typed.

Join

A network that joins is remembered in the board's EEPROM journal, and the board rejoins it at power-up with no host attached. Leave network drops the link but keeps what is remembered. The board remembers every network it has joined, up to ten; one it knows is marked KNOWN in the list and rejoins with no password typed, and at power-up the board joins the strongest known one in range. Forget takes the picked network off the list, or every network if nothing known is picked, and leaves it. The password is sent to the board as typed and is never stored by this page — the board does not print it back either.

Be a hotspot

Off

With no network to join, a board is reachable over this cable and nothing else. Told to be a hotspot, it carries its own: associate with it and everything is at 192.168.4.1.

It is a setting, not a rescue: the board does not become a hotspot because a network is missing, and does not stop being one because a network turned up. It does what it was last told, across power cycles. Stop lowers it and keeps the name and key; Forget key takes them out of the journal, which is what a board being passed on wants. An open hotspot is refused — the key is the only thing between the board's console and anyone in range.
The hotspot is a way to the board, not a way out. A laptop with a cable keeps the internet on the cable and reaches 192.168.4.1 over the hotspot, both at once. A phone has only the hotspot and its mobile data, so it keeps mobile data and sends http://192.168.4.1/ down that — switch mobile data off and the board answers. A VPN takes the default route and does the same to a machine that would otherwise have been fine. The association succeeds in every case, which is what makes it confusing rather than obvious.
